# FlickMemo Windows 0.1.0 開発記録

更新日: 2026-10-25。開発ブランチ: `codex/windows-desktop`。

## 構成

Tauri 2 / Rust / Windows WebView2 / SQLite。ElectronとChromiumの同梱は行わない。メモ画面と既存のファイル転送はWeb/PWA/拡張機能と共有し、Windows固有の処理を `src-tauri/` に分離した。

ウィンドウの×では、IndexedDBの書込み完了を待ってWebViewウィンドウを破棄する。保存エラー時は閉じずに通知する。転送中は中止するか確認する。トレイの「FlickMemoを開く」で再生成し、「終了」で常駐も終了する。

メモの未送信キューは既存のアカウント別IndexedDBに保持される。メモのクラウド同期・P2P転送はWebView側で動くため、画面を閉じた間の新しいメモの受信は再表示時に再開する。クリップボードの記録と許可された文字履歴の送信はRust側で続ける。

## 今回実装した機能

- 単一起動、トレイ、ウィンドウの破棄・再生成、終了、編集中メモの復元。
- `AddClipboardFormatListener` / `WM_CLIPBOARDUPDATE` による変更通知。クリップボードの定期ポーリングはしない。
- 記録は起動時OFF。アカウントが変わった時もOFFに戻す。画面を閉じるだけなら設定を維持する。
- 文字履歴をアカウント別SQLiteに保存。本文と更新トークンをWindows DPAPIで暗号化し、論理アカウントも復号の条件にする。既存メモのIndexedDBまでDPAPI暗号化に変更したわけではない。
- 1件64KiB、7日、1000件、文字合計16MiB、固定100件。期限切れの整理はバックグラウンドでも行う。未送信の削除キューも上限を設け、保存量が際限なく増える状態を避ける。
- 同一内容の連続コピーをまとめ、コピー回数を表示。アプリからのコピーには専用マーカーを付けて再取得を防ぐ。
- Windowsの機密クリップボード形式を尊重し、画面ロック通知と入力デスクトップの両方で取得を抑止する。既定で1Password、Bitwarden、KeePass、KeePassXCのプロセスを除外し、実行ファイル名の追加に対応する。
- 履歴の検索、50件ずつの表示、コピー、メモ化、固定、削除。画像は「画像の保存・同期はまだ実装されていません」と表示し、画像本体を読み込まない。
- Win＋Vに残っている履歴の手動取込み。履歴無効・拒否・取得失敗は理由を表示する。取得は同時に1回に制限する。
- クラウド送信は記録とは別スイッチで初期OFF。Firebaseの既存UIDに固定した送信キュー、受領後のACK、削除の墓標、通信断時の待機・再試行。画面なしで更新トークンを更新しながら送る。
- Web/PWA/拡張機能にも同じ履歴閲覧画面を追加。表示中だけ新しい50件を購読し、閉じる／アカウント変更で購読と本文DOMを解放する。
- 選択文字の明示的な30秒共有（4KiBまで）。自動送信・自動コピー・履歴への自動保存はしない。

## Googleログイン

WebView内でGoogleのログイン画面を開かず、標準ブラウザの既存の認証補助ページでアカウントを選ぶ。短命のランダムstate、IPv4ループバックのランダムポート、POST本文で結果を返す。トークンはURLに入れない。

受信側は正確なOrigin/Host、state、長さ、重複パラメーター、期限を検証する。受信口はアプリのログイン中だけ開き、接続数・読取り時間・本文サイズを制限する。WebViewを閉じた時は待受けも中止する。Firebaseの認証後に得たUIDと更新トークンだけをネイティブ側へ渡し、更新時もUID一致を確認する。

この方式には更新した公開 `/auth` が必要。Googleの実アカウントを使った最終操作は、アカウント所有者による確認を残している。自動テストで実アカウントへのログインまで確認したとは扱わない。

## 検証

- Web/拡張を含むNodeの回帰テスト: 53件成功。
- 実Chrome / 実Edgeの履歴UI: 各10項目成功。表示のXSS防止、Unicodeのコピーとメモ化、画像の未実装表示、固定・削除、購読解除、20回の再表示、取得中の閉じる操作を検証。OSのクリップボードへの実書込みは行っていない。
- 実Chrome / 実Edgeの既存WebRTC転送: 各12ケース成功。暗号化、0〜1MiBの転送、受信ACK、PNGの実デコードを確認。
- RustのDPAPI/SQLiteテストはGitHubのWindows環境で実行。暗号化、別アカウントでの復号拒否、Unicode、重複、上限、期限切れ、固定、ページサイズ、古いACKによる削除キューの誤消去を検証する。
- `scripts/measure-windows.ps1` は専用の一時DBとWebViewプロファイルで20回の生成・保存待機・破棄を検証し、自アプリの子プロセス込みPrivate Bytesを記録する。診断ウィンドウは非表示。実際のクリップボード本文・既存のブラウザプロファイル・実アカウントは使わない。
- ローカルのC++ Build Tools導入は自動承認レビューで「ポリシーによるブロック」と拒否された。このためネイティブのコンパイルはGitHubの標準Windowsランナーで行う。

2026-10-25のこのPCでの診断では、20回の開閉後、WebView2子プロセスの終了を確認できた。最後の待機時Private Bytesは6.37〜6.40MiB（自アプリ1プロセス）。非表示WebViewありの同じ診断では子プロセス込みで約118〜165MiBのサンプルもあった。履歴が空・記録OFFのテストであり、通常表示、履歴1000件、ファイル転送中のメモリ保証ではない。閉じた直後の一時的な値と子プロセス解放後の値は区別する。

履歴の `.indexOn: updatedAt` は、公開中の認可ルールを取得・比較したうえで2領域だけ追加した。既存の認可条件・公開ルームのルールは変更していない。ローカルのルールファイル全体を本番へ適用したものではない。

## まだ安定版と判断しない項目

- 実Googleログインとアカウント切替、実クリップボードの競合・画面ロック・スリープ復帰、実iPad PWAとの通し確認。
- インストーラーによるクリーン環境での導入・更新・アンインストール、24時間の待機、1000件の連続取得の負荷試験。
- 自動起動、変更可能なグローバルショートカット、10分停止、Windowsアプリ全般の選択文字の自動取得、署名付き自動更新。署名証明書は同梱せず、配布物は未署名の開発版。
- クラウドは現行Firebaseを使用する。Cloudflare D1/R2への移行と画像保存はまだ行わない。履歴のE2EEは未実装。
- 同期済みの他端末履歴は閲覧・コピー・メモ化に対応し、他端末の原本を直接編集する操作は提供しない。大きな時計ずれの調整、クラウドの期限切れレコードのサーバー側削除、削除墓標の長期運用は次の安定化で検証する。
- Win＋Vの取込みは履歴IDで重複を防ぐ（照合用IDは7日／2000件まで）。過去に明示削除した項目を同じIDで再び取り込まない設計とし、元のWindows履歴の削除は行わない。

## 開発コマンド

```powershell
npm ci
npm run check
npm run check:windows
npm run dev:desktop
npm run package:windows
```

ローカルビルドにはRust、Visual Studioの「C++によるデスクトップ開発」、Windows SDK、WebView2が必要。ユーザーがインストーラーを使う場合はRust/C++ビルド環境は不要。公式要件: https://v2.tauri.app/start/prerequisites/

Windows用のビルド先は `dist-desktop/` と `src-tauri/target/` で、Web配信用 `dist/` と分離する。CIの配布ファイルはGitHub ActionsのArtifactsに7日間保存する。インストーラー自体はクラウドへの履歴記録を自動でONにしない。
