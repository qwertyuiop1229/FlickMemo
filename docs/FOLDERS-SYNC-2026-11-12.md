# フォルダと起動設定の整理・Windowsの同期復帰（2026-11-12）

## UI

フォルダを常設一覧から、現在の分類名と件数を表示する44pxの1行の切替へ変更した。一覧は重ねて表示し、メモ一覧の高さを変えない。名前変更/削除は各フォルダの「…」から必要なときだけ表示する。選択時、外側のクリック、Escapeで一覧を閉じる。検索と新規メモを常時使える配置を維持する。フォルダ選択はキーボードフォーカス、件数、長い名前の省略、モバイル幅、テーマ色と減速設定に対応する。作成/名前変更ダイアログと本文の分類ピルも共通の余白と形へ整えた。

Windows起動設定は52×32pxのスイッチと44pxの操作領域、アイコン、短い説明、オン/オフの状態表示へ変更した。初回の案内も同じテーマで整え、勝手な有効化を行わない。保存失敗時は実際の状態へ戻す。Windowsのゲスト利用でも一般設定へアクセスできる。クラウド同期の設定表示は、ログインが必要/接続待ち/同期中/接続済みを実際の状態に応じて表示する。

## Windowsがローカルの古い内容を表示する経路

1. WebView2の画面保持と低メモリ休止から復帰したとき、更新確認しか行っていなかった。半開きのFirebase接続と古いSDKキャッシュから復帰しない場合を考慮し、Windowsの画面復帰/可視化とネット復帰でFirebaseの接続を更新する。Firebaseのget()はアクティブなリスナーのキャッシュを返す実装なので、get()だけを繰り返す方法にはしない。常設リスナーと既存の3方向マージ処理を使う。周期的なポーリングや画面再読み込みは追加しない。
2. 旧版で元メモと同じIDを復旧用に保護していた行は、クラウド値を受け付けない状態だった。IndexedDBの同一トランザクション内で原稿を新しい端末内復旧IDへ移し、元IDにはクラウドの最新内容を適用できるようにする。旧原稿は消さず、新しい復旧メモをクラウドへ自動送信しない。移動先IDの衝突時は処理を原子的に中止して原稿を保持する。

復帰処理は端末内保存の完了を待ち、アカウント/世代を照合してから行う。並行した復帰イベントは1件にまとめ、2秒以内の重複を抑止する。転送中は接続をリセットせず、P2P転送を妨げない。未送信の本文は既存のマージと控えによる保護を維持する。

## 検証

Nodeの回帰試験、Chrome/Edgeの実ブラウザでフォルダ操作/再読込/省スペースとモバイル表示、起動設定のAPIスタブで初回OFF/スイッチ/レスポンシブ表示を確認する。個人PCの起動登録や実クリップボードには触れない。

Firebaseエミュレーターでは同一アカウントのPWA相当/Windows相当の2クライアントを用意し、Windows側がオフライン中にPWA側で変更→get()は古いキャッシュを返す→再接続後に最新本文を受信する経路を確認する。Windowsのインストール/更新/20回の開閉と画面保持は使い捨てCI環境で検証する。
