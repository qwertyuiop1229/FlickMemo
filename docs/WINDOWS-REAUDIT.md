# Windows版 再監査

## 対象と前提

1.3.91のWindows/Rust、共通メモ画面、履歴アダプター、認証、署名付き更新、公開配信を再点検した。認証と更新の入力検証、アカウント切替、非同期処理、SQLite障害、期限・件数制限、終了時の保存を中心に、コード確認と再現試験を行った。全状況で不具合が存在しないことを保証する監査ではない。

## 見つけて修正した問題

1. **履歴からメモ化する途中のアカウント切替**: ローカル保存の完了後に現在UIDでクラウド送信するため、前アカウントの本文が新アカウントへ送られる可能性があった。開始時の所有者と認証世代を固定し、切替後の描画・送信を中止した。元アカウントのローカル保存は保持する。
2. **クラウド送信同意と除外設定の部分保存**: 2回のDB書込みの後半だけが失敗すると、画面では失敗でも送信同意だけが次回に有効になる可能性があった。暗号化後、両設定を同じSQLiteトランザクションで保存する。失敗を注入し、同意と除外設定の両方が巻き戻ることを試験する。
3. **共有停止・差し替えと遅い通信の競合**: 停止後に古い共有の書込みが終わって共有が復活する、古い終了タイマーが新しい共有を消す可能性があった。操作の世代管理と書込みの直列化を導入し、期限切れの送信も拒否する。
4. **購読解除後の遅い応答**: 閉じた履歴画面や切替後の画面へ古い受信内容を再描画する可能性があった。画面のライフサイクルを照合し、古いコールバックと通知を無視する。
5. **ページ送りボタンの再有効化**: 非同期操作終了時の共通処理が、端のページで無効化したボタンを再び有効にした。処理終了後も現在のページ・設定状態から有効/無効を再計算する。
6. **履歴更新時刻が逆行する可能性**: 高速コピーで増分補正された時刻に対し、固定・解除・削除が単純な現在時刻を使い、並び順と更新世代が逆行する場合があった。全操作で既存値より大きい更新時刻を使う。
7. **回復後や別アカウントへの古い同期エラー**: 通信エラーを保存エラーと分け、所有者と認証世代が一致する場合だけ反映する。成功時は同期エラーだけを解消し、画面の古いメッセージも消す。保存障害を誤って消さない。
8. **更新ダウンロードのメモリ上限の適用時点**: 上限は取得後の確認だった。HTTPサイズが大きければ事前拒否し、サイズ不明でも読み込み中に上限超過を拒否する。取得した全バイトを保持してから拒否する方式をやめ、公式updaterの署名・署名済みバージョン検証は維持する。
9. **コピー用マーカー登録失敗時の小さな割当て漏れ**: マーカー登録に失敗した場合はメモリを割り当てないようにした。

## 検証の構成

- Node: アカウント切替中のメモ送信抑止、共有登録中/書込み中の停止、古いタイマー、別UIDへの誤送信防止を追加。
- Rust: 設定書込み後半の障害によるロールバック、更新時刻の単調増加、古いアカウントの同期エラー拒否、通信回復と保存エラーの区別、サイズ不明の過大ストリーム拒否を追加。
- Chrome/Edge: 履歴画面15項目。ページ送り、通信回復時の表示、閉じた後の遅い受信を追加。認証の実HTTPS→ループバックPOSTも再試験する。
- Windows CI: インストール、再導入、20回のWebView開閉とメモ保存、アンインストール。さらに公開済み1.3.91から新版へ実際に更新し、同じWebView2プロファイルの日本語・絵文字入りメモ、タイトル、選択中メモを復元する試験を追加。
- 依存関係: npm/Cargoの既知脆弱性、Windowsの実依存経路、更新ファイルの署名と改変拒否を再確認する。

OSへの導入、CDPによる実WebView2操作、クリップボード書込みは使い捨てGitHubランナー内だけで行う。既存の実アカウント、個人ブラウザ、実メモ、個人クリップボードは使用しない。更新試験のデバッグポートと専用プロファイルはCIプロセスの環境変数だけで設定し、通常配布の設定は変更しない。

## 残る範囲

実Googleアカウントの最終操作、スリープ/ロック/アプリ間の実際の競合、24時間以上の連続稼働、ディスク破損やOS停止など全障害の組合せは別途実機確認が必要。DB権限試験は隔離エミュレーターであり、本番データに対する侵入試験ではない。

履歴の画像保存、履歴のE2EE、Cloudflare移行、クラウド期限切れデータ・削除墓標のサーバー側定期削除、Windowsのコード署名は未実装。ローカルのDPAPIは同じWindowsユーザー権限を奪ったプログラムからの完全な保護を保証しない。端末時計の大きなずれはクラウド表示に影響する。WebViewを閉じている間のメモ同期とP2P転送は停止し、許可済みの文字履歴送信だけがネイティブ側で続く。
