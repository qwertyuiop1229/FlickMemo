# 競合ループ・大容量転送・共有QR（2026-11-12）

## 競合の控えが増え続ける問題

Firebase Realtime Databaseは空のオブジェクトやnullの子を省略し、オブジェクトのキー順もクライアントと一致するとは限らない。新規メモの`codeCollapsed: {}`が省略された値とJSON文字列で比較され、誤った競合になり得た。さらに控えをクラウドへ自動送信していたため、同じ誤判定で控えから控えを作る経路があった。

空/null/省略とキー順をFirebaseの意味で比較する。本文文字列の比較でJSONの全文複製も行わない。控えはアカウント別のIndexedDBに`localRecovery`メタデータ付きで保存し、自動アップロード・クラウドの不存在を理由にした削除の対象から外す。控え自身の競合は同じIDの端末内保護へ切り替え、新しい控えを再帰生成しない。古い版が未送信のまま残した控えも再接続前に端末内保護へ移す。

同じ内容は重複作成しない。自動控えは元メモ当たり10件、アカウント当たり100件、本文/タイトルのUTF-16概算合計16MiBまでとし、上限時は現在の下書きを保持して自動同期を保留する。これらは控えの自動生成の上限であり、ファイル転送サイズの上限ではない。保存失敗・上限時に原稿を捨ててサーバー値へ置き換えない。通知も元メモ単位でまとめる。

復旧メモには「この端末の復旧メモ」と「新しいメモとして同期」を表示する。コピー先は新しい通常IDで作り、本文・タイトル・分類・ピン・コード折りたたみ状態を反映する。元の控えは保持する。旧版由来の控えや別タブの未送信原稿を盲目的なキャッシュ更新で破棄しない。

別タブが同じIDを復旧メモとして保護した後の、古いタブからのキャッシュ上書き・キャッシュ削除もIndexedDBの同一トランザクション内で拒否する。明示的な復旧メモ編集/削除だけを許可し、クラウドへの書込/削除前にも永続化された保護状態を確認する。

クラウドルールでも、`conflictOf`付きの新しいノートの作成を拒否し、旧クライアントによる新規控えの増殖を止める。既に存在する控えの編集/削除と通常メモの操作は維持する。検証済みルールはWebと同じ`npm run deploy`で配信する。

## 大容量ファイルとiPhone PWAの容量

ファイル本体をアプリのIndexedDB/OPFSへ保存せず、複数選択も巨大ZIPへまとめず元ファイルを順に送る。読出しは32KiB以下、受信確認待ちは256KiB。新たにDataChannel自身の送信待ちバッファにも約256KiB（最大で次の1チャンク分を超えることあり）の制限を付け、相手の確認だけに依存しない。完了・失敗・中止後に入力と送信待ちのFile参照を解放し、送信履歴には名前/サイズ等だけを残す。

接続情報・ファイル読出し・暗号化の待機は、切断や中止で終了できる。チャンクごとに同じ完了Promiseへの待機を蓄積する実装は避け、待機中の処理を1件だけ保持する。Windowsと対応PCブラウザは、ユーザーが選んだ保存先へ小分けに直接書き込む。通常受信のメモリ保護64MiBと、直接保存時の空き容量/ファイルシステム等の制約は残る。

iPhoneのファイル選択時にWebKit/iOSが作る一時コピーの即時削除はWebアプリから保証できない。メモを消す全ストレージ初期化は行わず、アプリ側で送信ファイルの永続コピーやZIPを作らず、参照を解放する。全サイズ/全端末で停止や容量増加が絶対に起きないという保証ではない。

## 共有リンクのQRコード

リンク作成後のQRボタンから表示する。公式URL・room ID・完全な`#key`を含むリンクだけを端末内で描画する。QR外部サービスへ共有キーを送らない。エンコーダーは操作時だけ読み込み、停止・アカウント切替・閉じる時に表示画像を破棄する。遅れて終わった古い描画が、新しい共有のキーを表示しないよう世代を照合する。モバイル幅にも対応したテーマ色のダイアログと、読み取り用の高コントラストのコードを使用する。

## 通知

右下の通知は`box-shadow: none`と既存テーマ変数を維持する。実ブラウザで影なしを確認する。

## 依存ライブラリの再監査

前回の監査以降に公開されたRUSTSEC-2026-0459（細工されたSQLiteとWALファイルを開いた場合のメモリ漏えい）に対応し、rusqliteを0.41.1、同梱SQLiteのlibsqlite3-sysを0.39.1へ更新する。FlickMemoは自身のアプリデータベースを使用し外部SQLiteをインポートしないが、修正版を同梱する。RUSTSEC-2026-0486に対応したrustix 1.1.6へもロックファイルを更新する。更新後は旧版データを維持するアップグレードとネイティブDB試験をCIで実行する。

## 検証

空の設定のFirebase往復、キー順の違い、20回の新規メモと保存/エコー、同じ競合30回、空のメモ50回、控え自身の競合、上限、再読込、古い送信待ちの隔離、通常メモへの明示コピー、キャッシュの未送信原稿保護を試験する。

40GiBというサイズ情報の仮想ファイルで、32KiB以下の開始/読出し/中止を確認する（40GiB全体を実転送した試験ではない）。別途80MiBを実WebRTCで全バイト検証し、PNG復号も試験する。バッファ待ち・遅い読込みの中止・ディスク障害・切断の回帰試験を含める。QRはChrome/Edgeで実際に画素から復号し、共有キーまで一致、停止後の消去、外部QR通信なしを確認する。

Windowsの実インストール/更新/開閉と、Firebaseの権限/控え新規作成拒否/旧控え編集は使い捨てWindows CIで確認する。個人端末の実クリップボード、入力フック、起動登録、インストーラーは操作しない。実iPhoneの一時領域や全ファイルシステムまでは実測できていない。
