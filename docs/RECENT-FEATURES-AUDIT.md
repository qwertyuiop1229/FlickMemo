# 最近追加した機能の再点検（2026-10-27）

対象: Windowsカラーピッカー、設定、クリップボード記録、Google認証の受渡し、自動更新、履歴・選択文字の同期。Windows CIの不安定な採色試験は1.3.99で修正・全工程成功済み。原因と修正はCOLOR-PICKER.mdを参照。

## 今回修正した問題

- Windows設定の初期読込み前にコピー形式を変えると、既定の有効化・履歴保存・キー設定で保存済み設定を上書きできた。全変更操作を初期化完了まで無効化し、Windowsではブラウザ保存設定を読まない。初期化失敗後もブラウザの非マーカーコピーへフォールバックしない。
- 設定取得からイベント購読までの間に選んだ色が画面に反映されない場合があった。先に購読して初期化中のイベントを保持し、設定確定後に表示する。起動時にはネイティブ保存済みの直近色を表示する。
- 起動タイムアウト後に遅れて生成された採色ウィンドウ・グローバルキー、クリップボード通知が残り得た。呼出し側への起動通知が失敗したら通常の後片付けへ進み、登録を解除する。
- 非記録用クリップボードマーカーの確保に失敗しても、アプリ自身が書いた内容を自動履歴に取り込まないよう、書込み元プロセスIDによる除外を追加した。自己プロセスから外部コピーを模擬する例外は診断モードだけ。

## 確認した保護

- 認証受渡しはIPv4ループバック限定、公式HTTPS Origin・Host・ランダムstate照合、重複ヘッダー/フォーム拒否、サイズ・時間制限。トークンをURLに含めない。
- 更新は公式配布URL・バージョン・サイズ制限と署名を検証。ダウンロード後の編集も保存し、保存失敗時は適用せず、ネイティブでインストール前にも検証する。
- 履歴同期はログイン中の所有者・世代番号を照合し、アカウント変更後に古い処理を別アカウントへ書かない。選択文字の共有は期限付き・直列化し、停止後の遅延書込みを抑止する。
- 採色画像や最近の色はクラウドへ送信しない。設定・色は端末単位。画面全体の画像を保持しない。

## 検証と限界

初期化遅延中の設定変更・コピー、保存済みの無効設定保持、初期化中イベント、初期化失敗、直近色復元の回帰試験を追加。自己プロセス・別プロセス・所有者不明・診断時の除外判定をRustで試験する。

実ブラウザは新規の隔離プロファイルで、採色/コピーは合成実装を使用。OSの入力・採色・コピーは使い捨てWindows CIだけで検証し、個人端末のクリップボードを変更しない。

Googleの実アカウントログイン、長時間常駐・あらゆる端末の休止/ロック/高DPI/HDRは網羅していない。Windowsコード署名は未導入であり、更新ファイルの検証署名とは別。未知の不具合や脆弱性が存在しないことを保証する監査ではない。
