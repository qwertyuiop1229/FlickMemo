# ファイル転送・画像コピーの修正 — 1.3.80

2026-10-24。対象はWeb/PWAとChrome/Edge拡張。Windows版の実装は行っていない。

## 報告された現象

iPadのPWAからChrome拡張への送信で、`Decryption fallback (raw chunk used)` が繰り返し記録され、その後PNGをクリップボードへ書く際にDataErrorが出た。

調査時点の公開版は1.3.79で、このfallback文字列は公開JavaScriptから除去済みだった。そのため、少なくともログを出した環境に旧コードが残っていると判断できる。ただし実際の両端のバージョンや暗号鍵は取得できておらず、鍵不一致の発生経路をiPad実機で確定したわけではない。

旧処理は復号できなかった暗号文をそのままファイルとして扱い、PNGというMIME名だけでコピーを試していた。この場合、画像デコーダーは画像として読み込めない。公開サイトの更新だけでは、展開して導入した拡張機能のプログラムは置き換わらない。

## 今回の修正

- 転送プロトコルv2: HELLO/ACKで互換性、モード、共有鍵の一致を確認してからファイル本体を送る。無反応な旧クライアントにはデータを送らず、両端の更新を案内する。
- SCTPのメッセージ上限を両側で照合し、最大32KiBのチャンクから安全なサイズを選ぶ。暗号化の28バイトの増加分も含める。
- 受信・復号が完了した分だけ送信枠を回復する。速い送信側が、遅いiPad等の受信待ちメモリを使い切らないよう、未確認量を約256KiBに制限する。
- 転送IDとチャンク位置をAES-GCMの追加認証データへ含め、別ファイルや別位置の暗号文の使い回しを拒否する。
- 暗号化設定はファイル単位で固定する。送信途中でトグルを変えても、一部だけ平文へ変わらない。
- 接続や鍵が変わった後に、古い非同期鍵生成の結果をキャッシュしない。
- 復号失敗、壊れたサイズ、切断、受信の停止は転送失敗として処理する。壊れたファイルを受信履歴へ登録しない。
- `file_received`の確認応答を待ってから送信成功とする。進捗が100%でも確認前は「相手の受信確認中」と表示する。相手のアプリが受信したことの確認であり、ユーザーがディスクへ保存した保証ではない。
- PNGを含む画像は、コピー時にデコード・サイズ確認・PNGへの再変換を行う。変換不能なら失敗を表示し、同じ壊れたデータを何度もコピーしたり、勝手にbase64へ置き換えたりしない。
- Safariの操作起点の制約に合わせ、ClipboardItemへ変換Promiseを渡し、クリック中にclipboard.writeを呼ぶ。
- Blob URL、キャンバス、タイマーを変換の成否にかかわらず解放する。巨大PNGの寸法はデコード前に検査する。画像コピーは16MiB・約8百万画素を上限とし、それを超えるものは元ファイルの「保存」を案内する。転送自体は64MiBまで。
- ZIP内の重複名が、元からある `a_2.txt` 等を上書きする問題も修正。エントリー名から親ディレクトリ移動も除く。
- PWAの入口 `/` 等にもno-storeを設定し、古いHTMLが残る問題を軽減する。拡張の更新ボタンは、パッケージの入替え手順を案内する。

## 検証

- 単体・回帰テスト47件: 旧版の拒否、異なる共有鍵、遅い復号、ACKの欠落、改ざん、暗号化の途中切替、0/1/32767/32768/32769/262145バイト、16KiBの通信上限、画像の破損・変換失敗・権限拒否、ZIPの上書きなど。
- 独立したテスト用Chrome 156.0.8078.47とEdge 156.0.4314.42で、実際のRTCPeerConnection/DataChannelを使用。各12ケースで暗号化した0/1/32768/32769/1MiBのデータをバイト単位で確認。通常セッション・共有リンクの両モード、遅い復号を確認。
- 両ブラウザで、実Canvasで作ったPNGを転送し、画像デコーダーとPNG変換まで確認した。OSの個人用クリップボードはテストで書き換えていない。
- 画像コピーのSafari用Promise呼出順は模擬環境で検証。iPadの実Safari/PWAのクリップボード許可や、実端末間のFirebaseシグナリングはこのPCからは未検証。
- 依存パッケージ監査の検出0件。DBルールは今回変更・デプロイしない。

テストブラウザは毎回独立した一時プロファイルで起動し、個人用のChrome/Edgeプロファイルを使わない。

再実行:

```powershell
npm test
node node_modules/vite/bin/vite.js --host 127.0.0.1 --port 5174 --strictPort
# 別ターミナル
npm run test:browser
$env:TEST_BROWSER_CHANNEL='msedge'
npm run test:browser
```

## 利用側で必要な更新

1. Chrome側はダウンロードページから最新ZIPを取得し、現在読み込んでいる拡張フォルダのファイルを更新する。その後 `chrome://extensions` でFlickMemoを再読み込みし、サイドパネルを閉じて開き直す。拡張の削除やメモの保存データ削除は不要。
2. iPadのPWAは設定の「更新を確認」で更新し、必要ならPWAを終了して開き直す。両端の設定に1.3.80以降が表示されることを確認する。
3. 共有リンクを作り直し、元ファイルを送り直す。既に壊れた暗号文として保存された画像を、そのファイルだけから復元することはできない。

プロトコルを更新しているため、古い1.3.79以前の端末との転送を許可しない。新しいエラーが出た場合は、送信・受信の両側のバージョン、接続方式とエラーを確認する。
