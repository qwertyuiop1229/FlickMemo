# Windows版 配布・安定化監査（2026-10-25）

既存の `WINDOWS-IMPLEMENTATION.md` は0.1.0初版の記録。本記録と`DEPLOY.md`はその後の共通バージョンによる公開配信と修正を記録する。

## 修正内容

- 通信断中のコピー通知が待機時間を無視し、同期リクエストを繰り返す問題を修正。単調時計で60秒から15分の再試行間隔を保持する。
- 削除済み履歴が「新しい50件」を占有し、古い有効な履歴が見えなくなる問題を修正。原本の削除と別領域の墓標作成を1回の原子的更新にする。既存のアップロード済み墓標は一度だけ再送対象に戻す。
- 日本語検索の256文字制限を、UTF-8バイト数ではなく文字数で判定する。固定100件の状態で、固定済み項目への再度の固定操作は成功として扱う。
- 遅れて届いた前アカウントの設定・履歴操作を、ネイティブ側の期待UID照合で拒否する。
- コピーによる自動更新で除外設定の編集中テキストやフォーカスが失われる問題を修正。設定保存を直列化し、チェック切替では未保存の除外設定を勝手に保存しない。
- 履歴画面内のCtrl+Fが背面メモの検索まで動かす問題、閉じた画面の遅延処理が再表示した画面を消す問題を修正。
- チャコールと暖色を中心に履歴画面を整理。設定は折りたたみ、文字・画像未対応表示・同期状態・50件単位のページ送りを明示する。モバイル入力は16pxを指定する。
- WindowsのバージョンをWeb・拡張と同期。更新ボタンとダウンロード案内は、許可した公開URLを標準ブラウザで開く。
- 起動エラーを黙って終了せず、データ削除を促さない案内を表示する。
- 配信の同時実行、古いキャッシュ内インストーラーの誤配布、コミットやハッシュが異なるファイルの配布を防止する。Actions YAMLも配信前に解析する。

## 検証の範囲

### 実際の公開配信

`npm run deploy`で1.3.88のWeb/PWA/拡張ZIP/Windows配布情報をFirebase Hostingへ公開した。公開`version.json`、`windows/release.json`、拡張ZIPのバージョン・内容一致、GitHubの2実行ファイルのMZヘッダー・サイズ・SHA-256一致を確認。GitHubにログインしていない新しいブラウザで、公開ページのボタンをクリックして`FlickMemo-Setup.exe`がダウンロードされ、検証済みハッシュと一致することまで確認した。

公開配布ページ: https://flickmemo-qwe.web.app/download#http-windows

GitHub Release: https://github.com/qwertyuiop1229/FlickMemo/releases/tag/v1.3.88

公開ページのPC/スマホ表示、無効な配布情報ではボタンを有効化しないこと、設定のWindows案内が拡張機能の直前に表示されることも成功した。画像はローカル`desktop-reports/public-settings.png`と`public-download-mobile.png`に保存している。

最初のHosting配信ではSparkプランの実行ファイル禁止によりエラーになった。実行ファイルをGitHub Releaseに置き、Hostingには検証済み配布情報だけを置く構成に修正し、再配信に成功した。拡張子変更等で制限を回避したり、課金プランを変更したりしていない。

### ネイティブ検証と測定

配布ビルド1.3.88（`a1d049bb8c0abf7927326edeea829ffe3c04fbd8`）のWindows CIは全工程成功。Rust13件、隔離DBの自己アカウントCRUD・他人/未認証の拒否・75件から50件削除して25件表示・既存メモ保全、インストーラー生成、実OSクリップボード通知、日本語メモを保持した20回のWebView破棄・再生成を検証した。

CI記録: https://github.com/qwertyuiop1229/FlickMemo/actions/runs/40193860694

このCIの最後の待機サンプルは1プロセス・Private Bytes約6.52〜6.55MiB、最後の非表示WebViewありサンプルは子プロセス込み約135.88MiB。旧1.3.87ビルドをこのPCで20回開閉した診断も成功し、最後の生存中の待機サンプルは約17.57MiB、非表示WebViewありでは約225MiBだった。環境・タイミングによる差があるため、最小値を通常利用時の保証値として扱わない。

DBの検証は`demo-flickmemo`のローカルAuth/Databaseエミュレーターに限定し、本番のメモや認証状態には触れない。ブラウザ検証は専用の新しいヘッドレスプロファイルを使用する。OSのクリップボードを実際に変更する試験は使い捨てGitHubランナーだけで行う。

## 残る確認項目と仕様

バグがないことを保証する監査ではない。実Googleログインとアカウント切替、iPad PWAとの通し操作、スリープ復帰・画面ロック・実アプリとのクリップボード競合、クリーン環境のインストール/更新/アンインストール、24時間連続稼働は追加の実機確認が必要。

記録は起動時OFF。クラウド送信は別スイッチで初期OFF。画像保存、Cloudflareへの移行、履歴のE2EE、署名付き自動更新は未実装。選択文字の共有は明示操作で行う。Win+Vの過去履歴は手動取込みで、通常の新しいコピーはWindows変更通知から取得する。

メモ同期とP2P転送は画面が開いている間に動作し、画面を閉じるとWebViewを破棄する。文字履歴の取得と許可済みの送信はネイティブで続ける。初版の約7.48MiB待機という計測値は条件付きの旧ビルド結果で、新しい版や通常表示時のメモリ保証には使わない。

クラウドの履歴期限切れと墓標のサーバー側長期削除は未整備。検索はローカルでは保持中の全履歴、クラウドでは購読する新しい50件が対象。DPAPIは同じWindowsユーザー内の悪意あるプログラムからの完全な防御を保証しない。
