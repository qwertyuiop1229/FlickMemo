# Windowsの接続方式とメモ操作メニュー（2026-11-12）

## 再接続待ちのままになる問題

前回119の対策は接続の再開と旧復旧IDの分離までで、初回の接続方式を見落としていた。Firebase SDKはWebSocketの失敗履歴（`firebase:previous_websocket_failure`）や永続ストレージが使えない状態により、script/iframe型のlong pollingから接続を始める。Windows版のCSPは外部スクリプト実行とフレームを禁止しているため、その方式では接続が成立せず、単にgoOffline/goOnlineを繰り返しても改善しない。

Windowsと拡張機能では、データベースの生成前に公式SDKのforceWebSockets()で対応方式を選択する。CSPは緩めず、過去の失敗フラグやメモのローカル保存を消す対策も行わない。通常Web/PWAの自動方式選択は維持する。

Windowsで切断が続くときは20/40/80/120秒へ間隔を広げて再試行する。接続成功で停止/リセットし、ログアウト/アカウント変更で古い試行を無効化する。背景・オフライン・ファイル転送中には動かさず、画面復帰/通信復帰/転送終了で再開する。タイマーは1つ、並行した再試行も1つに抑える。ステータスはキーボードでも押せるボタンにし、切断中に押すと明示的に再接続する。

## メモ操作

通常メモの削除ボタンの隣に「…」を設置し、PCの右クリックでも同じメニューを開く。フォルダ変更とピン留めに対応する。移動先では現在のフォルダをチェックで表示する。画面外へのはみ出し、Escape、矢印キー移動、フォーカス、名前の省略、アカウント変更後の古い操作、削除済みフォルダを考慮する。表示は既存テーマのMaterialスタイルとネイティブPopoverを使用し、非対応時は代替表示する。

すべてのメモではタイトル下に小さなフォルダアイコンと保存先を表示する。フォルダで絞り込んだ場合は現在の分類が切替部に示されるので、各行の同じラベルは省いて重複を減らす。

別のメモをメニューから変更する場合にも編集中メモの保存待ちを確定し、本文・タイトル・選択・プレースホルダーを変更しない。従来のアクティブ行だけの更新処理も、別IDを操作したときにアクティブ行のタイトルへ誤反映しないよう修正する。

## 検証

実際のWindows CSPを適用した独立Chrome/Edgeコンテキストで、失敗履歴を仕込むと旧方式で接続が止まり、対応方式では本番Firebaseの`.info/connected`がtrueになることを確認した。アクセスするのは接続状態だけで、利用者のメモやアカウントの読書きは行わない。

Windowsの使い捨てCIにも、失敗履歴がある状態から実WebView2と本来のCSPのまま実Firebaseへ接続する確認を追加する。これは隔離診断モードの最初の準備完了より前だけに実行し、通常利用の開閉では診断の通信やフラグ書込を行わない。接続失敗時は診断を失敗させる。

再試行のバックオフ/停止/所有者切替と遅い旧試行、通常モードで診断を呼ばないこと、失敗時に準備完了扱いにしないことをNodeで検証する。Chrome/Edgeでは右クリック/ボタン、移動/ピン、編集中の保持、保存先表示、選択済みフォルダ、PC/スマホ幅とEscapeを確認する。

参考：[Firebase SDK forceWebSockets](https://firebase.google.com/docs/reference/js/database#forcewebsockets)。実際の利用者のWindows環境やVPN/プロキシ等を操作する試験ではない。ネットワーク自体が通信を拒否する場合の接続は保証せず、下書きは端末に保護する。
