# 採色・分類・起動・同期・大容量転送（2026-11-03）

## 変更内容

### カラーピッカー

UIと機能、キー・形式・最近の色は維持。位置の追従は15msタイマーで約60fpsを目標にし、7×7の採色は約30ms間隔に分離。変化のない色では再描画を省く。オフスクリーン画像・フォント・ペンを採色中だけ再利用し、各セルのブラシはストックオブジェクトを使う。二重バッファで描画し、キャンセル/結果表示終了後に解放。OS・負荷により実際のfpsは変動する。

### メモの分類

サイドバーに「すべてのメモ」「未分類」とフォルダ・件数を表示。作成・名前変更・削除、メモ上部の移動セレクト、フォルダ内での新規メモ作成を用意。フォルダ削除では本文を消さず未分類として扱う。モバイルではエディタのフォルダボタンから一覧を開ける。名称はテキストとして表示し、60文字、最大200件のメタデータに制限。軽いフォーカス/押下/ダイアログアニメーションと動きを減らす設定に対応。

フォルダはアカウント別にキャッシュし、クラウドでは `users/{uid}/folders/{id}`、メモには `folderId` を保存。フォルダ削除はメタデータの墓標にし、全メモの一括書換えを避ける。未同期の変更は端末に保持し、アカウント切替時に前のユーザーのイベントを破棄する。

### Windows起動と通知領域

最初の起動時に自動起動の可否を質問し、既定で勝手に有効化しない。「設定 → システム」のスイッチで変更可能。HKCUのRunに現在の実行ファイルを引用符付きで登録する。設定DBへの保存失敗では以前のRun値へ戻す。Windows自身のスタートアップ設定や管理者のポリシーは優先される。

トレイの左クリックでは、ウィンドウが非表示・最小化・他アプリの背面なら再表示する。表示済みで最前面ならメニューを開く。右クリックのメニューは維持する。自動起動のアンインストール時削除/更新時保持はTauri標準NSISの処理を使用する。

### 古い内容が戻る問題

旧処理は、起動時に端末のpendingメモをクラウド確認前に丸ごとsetしていた。また、保存内容が変わっていなくても閉じる時の保存でpendingになり得た。変更のない保存ではpendingを立てず、編集前のベース値と変更項目を保持する。

起動時はリモートを確認してから差分を再適用。通常保存も短命の購読でトランザクション対象のキャッシュを確保し、Firebaseトランザクションで最新値に対して項目単位で照合し、フォルダ移動が別端末の本文変更を上書きしないようにする。同じ本文などが両端で変わっていればリモートを原本とし、端末の変更を別IDの「競合の控え」に残す。時刻の新旧だけで本文を決定しない。オフラインや保存拒否では同期待ちを表示し、再接続時に安全な再試行を行う。未同期データやアカウント別キャッシュを一括削除しない。

遅延フォーカスが素早いタイトル入力を本文へ送る場合も再現したため、メモ選択時のフォーカスを同期的に行い、後から入力先を奪わないようにした。

実質的な差分のないトランザクションはリモートの更新日時を保持する。確定結果の別イベントが来ない場合にも、送信時から追加編集がないことを確認してマージ後の本文を画面とキャッシュへ適用する。

### 大容量ファイル

複数選択時もZIPへ全体展開せず、元ファイルを順に読み、32KiB以下のチャンクと256KiBの送信クレジットで送信する。受信側が書込みを終えた分だけクレジットを返す。完了/失敗/中止後は送信キュー・File inputの参照を解放し、送信履歴にファイル本体を保存しない。

受信側で「大容量受信の保存先を選ぶ」を明示的に押すと直接保存に切替。WindowsではOSのフォルダ選択とRustファイルI/Oを使い、32KiBのバイナリIPCをバックグラウンドで書き込む。部分ファイルは専用名の.partにし、長さ・fsync後に上書き不可の移動で確定。中断時は部分ファイルを削除する。PCの対応ブラウザではFile System AccessのWritableを使う。アプリのOPFS/IndexedDBへ転送本体を複製しない。保存先の認可はセッション中だけ保持し、アカウント切替で解除する。

受信側は自分の受信能力を交渉し、古いクライアントや直接保存非対応のブラウザには無制限の受信を送り付けない。直接保存ではアプリ固定のサイズ上限を設けないが、空き容量・ファイルシステム・OS・ブラウザ上限は残る。Safari/iPhone等の直接保存非対応環境の通常受信はメモリ保護の64MiBまで。iPhoneから対応PCへの大容量送信はこの受信制限とは別。

iOSのファイル選択時にWebKit/OSが作る一時ファイルの即時削除はWebアプリでは保証できない。アプリが新たに作るZIPや送信本体の永続保存は避け、参照を解放する。強制終了・電源断・保存先の権限剥奪などでOS上の部分ファイルが残る場合はある。どれほど大きくても必ず成功/低メモリとなる保証ではない。

### 通知

右下通知の影と背景ぼかしを除去し、背景・枠・文字・アイコン・アクションを既存テーマ変数へ統一する。

## 検証

Nodeの回帰試験、Chrome/Edgeの新規ヘッドレスプロファイル、合成データの実WebRTC転送、使い捨てWindows CIで検証する。個人端末のOSクリップボード・入力フック・自動起動設定・実インストーラーを操作しない。

含める試験: フォルダCRUD/移動/アカウント分離、古いキャッシュと時計ずれ/本文競合/項目別マージ、トランザクションのルール検証、自動起動の初回選択・保存失敗復帰・Windowsの登録/解除・アンインストール、ネイティブのバイナリIPCと実ファイル、80MiBの仮想ファイル転送（集約Blobなし）、ディスク障害/中止/遅延保存先の後始末、採色のCPU/メモリ/fpsと正確なコピー。

実Googleアカウント、実iPhoneの大容量ファイル、全OS/全ファイルシステム、長時間常駐、実ユーザー環境の通知領域クリックまでは網羅していない。
