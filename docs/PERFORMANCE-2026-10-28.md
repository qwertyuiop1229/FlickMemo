# 採色・画面保持・画面移動の改善（2026-10-28）

## 変更内容

- Windows採色の50回/フレームのGetPixelと毎フレームのDwmFlushを除去。7×7・196バイトのDIBを採色中だけ再利用し、1回のBitBltで取得。移動中は約15fps、停止中は最大5fps。ウィンドウ領域はサイズ変更時だけ作る。確定した色は従来どおり非表示後に1ピクセルを読み直す。
- グローバルマウスフックを専用入力スレッドへ移動し、GDIや描画待ちから分離。フックではイベントの転送のみを行い、キャンセル・終了直後から入力を通過させ、スレッド・フック・バッファを解放する。休止中には採色タイマー・採色バッファ・入力スレッドは保持しない。
- 左上のアプリ名/ロゴと条件付きの戻るを、常設の戻る・進むボタンへ変更。画面移動は端末内の最大100件、メモ本文を保存せず、戻る/進む可否をdisabledに反映。消えたメモはスキップし、アカウントの切替・データ消去で移動履歴をリセット。本文のUndo/Redoとは別。
- Windowsは保存待機後、WebViewを破棄せず非表示にしてTrySuspend・低メモリ目標を要求。再表示はResumeで同じDOMを使う。隠れた画面への履歴更新通知を抑え、再表示時に再取得。トレイの終了・更新適用は保存後にプロセスを終了する。

## 設計上の限界

画面を残すため、WebViewを破棄していた旧版と同じ最低メモリにはならない。休止はランタイムの最善努力で、WebRTCなどが動作中の場合は休止できないことがある。画面の同期・選択共有は休止中に遅れ得るが、ネイティブのクリップボード記録・履歴同期は別スレッドで継続する。

Web/PWA/拡張はブラウザ標準EyeDropperを使用し、独自の画面キャプチャや常時ポーリングを追加しない。任意のOS・GPU・画面構成に対する「絶対に重くならない」保証ではない。HDR/広色域の厳密な測色は対象外。
